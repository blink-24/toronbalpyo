## 검증 경계

이전 2차시 실제 Google 왕복·데스크톱/모바일 크기 검사는 [자체 검토 기록](AUDIT_20261027.md)에 있다. 이번 4차시의 자동 브라우저 검사는 실제 서비스 모듈에 메모리 저장소를 연결하며 외부 Google 요청을 모두 로컬 fixture로 우회한다. 교사 암호·학생 입력은 합성 시험값이고 실제 Google 행이나 AI 호출을 만들지 않는다. 이 시험을 실제 Google 저장 완료로 표현하지 않는다.

학교 실제 기기·망 및 소유자 새 서버 배포 후 인증·저장 검증은 남아 있다. [서버 갱신 순서](SERVER_UPDATE.md)를 따른다.

## 5.1.0 구현·게시 결과

[PR #9](https://github.com/blink-24/toronbalpyo/pull/9)는 `e76e5f2e26efc4b7fa6f574c53b6a97b4c3236ea`로 병합되었다. [Pages 게시](https://github.com/blink-24/toronbalpyo/actions/runs/40495061769)와 [최종 브라우저 검사](https://github.com/blink-24/toronbalpyo/actions/runs/40494815236)가 성공했다. Node 109개·생성 GAS 일치·정적 빌드도 통과했다.

게시 뒤 실제 공개 API에서 현재 반 수가 13으로 확인되었다. 기존 검사와 교사용 목록의 고정 11반 가정을 제거해 실제 config를 따르도록 보완한다. 사용자 운영 설정을 11로 되돌리지 않는다. 최초 접속 검사 실패 40495061815는 반 수 불일치이며 서버 ping은 정상 통과했다. 수정 후 실제 접속 검사 결과는 후속 PR과 이슈 #8에 기록한다.

## 새 서버 연결 확인

사용자가 새 배포 주소를 제공했다. `config.js`를 해당 주소로 교체하고 [실제 API 검사40497640714](https://github.com/blink-24/toronbalpyo/actions/runs/40497640714)에서 버전5.1.0·구현차시2/4·운영13반·4차시4문항·대본모드를 확인했다. 공개 설정의 비밀값 비노출, 익명집계, 무암호 교사 조회·개방변경 거부, 잘못된학번 POST 거부를 통과했고 학생 기록·개방 설정은 변경하지 않았다.

확인 시점의 개방차시는2뿐이다. 4차시 개방은 교사가 교사용 화면에서 선택한다. 실제 암호를 대화에서 받지 않는다.

동일 데이터베이스 `l4_sessions`의 기존28개 헤더를 정본과 대조하고 오른쪽 AC:AM에11개 항목만 추가했다. 기존열·행·설정은 유지했고39개 전체헤더의 재조회 일치를 확인했다. 새열에는 기존이웃의 서식만 복사하고 새열너비만 자동조정했다. 실제 모둠의 정상 제출·교사로그인·학교기기 검증은 별도다.
