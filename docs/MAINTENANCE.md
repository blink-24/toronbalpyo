# 관리자 유지보수 안내

이 문서는 저장소·서버 관리자를 위한 것이다. 학생 활동 화면에 구현·배포 설명을 옮기지 않는다. 실제 계정·저장소·연결 상태는 `DEPLOYMENT_STATUS.md`에서 별도로 관리한다.

## 배포와 연결의 구분

| 상태 | 의미 | 관리자 확인 |
|---|---|---|
| 로컬 검사 통과 | 지정된 코드·가상자료 시험 통과 | `npm test`, `npm run check`, `npm run build` 결과 |
| Pages 배포 성공 | 검사한 `dist/` 정적 파일 공개 | Actions의 Pages 실행·배포 URL |
| API 주소 설정 | `config.js`에 서버 실행 URL 존재 | 주소가 실제 배포와 일치하는지 |
| 기능 연결 확인 | 제출·공유·교사 조회가 실제 시트와 왕복 | 가상 입력 제출·재시도·중복·조회 결과 |
| 수업 전 확인 | 학교 기기·망·18분 운영 검토 | 기기 시연·기록 범위·보관 안내 |

주소가 있다는 사실만으로 실제 연결을 확인했다고 기록하지 않는다. API 주소가 없으면 Pages 작업 요약에 기능 연결 미완료가 표시된다. 오류를 감추기 위해 서버 제출 완료 표시를 임의로 만들지 않는다.

## 최초 설정

1. 사용자가 지정한 GitHub 저장소와 기본 브랜치를 확인한다. 이 워크플로의 대상은 `main`이다.
2. 관리자 또는 유지관리자가 **Settings → Pages → Source: GitHub Actions**를 선택한다. `github-pages` 배포 환경의 대상 브랜치도 `main`과 맞춘다.
3. 필요한 Apps Script 서버와 스프레드시트를 준비하고 교사 접근 범위를 확인한다. 비밀키·교사 암호·AI 설정은 서버에만 둔다.
4. `config.js`의 `window.CLASSROOM_CONFIG.apiUrl`에는 공개 실행 URL만 넣고 PR로 반영한다. 저장소에 계정 자격 증명이나 학생 기록을 넣지 않는다. 게시 앱은 이 배포 설정 주소만 사용하며 기기에 저장된 임의 주소 덮어쓰기와 화면의 주소 입력 기능은 제공하지 않는다.
5. 가상 입력으로 질문·피드백·최종 제출을 왕복하고 시트의 한 행·집계·교사 조회를 대조한다. 같은 제출 재전송이 중복 행을 만들지 않는지도 확인한다.
6. 코드·시트·설정의 확인 결과와 날짜를 배포 상태에 적는다. 실제 학생 기록을 검증용으로 재사용하지 않는다.

GitHub의 [사용자 지정 Pages 워크플로](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)와 [게시 소스 설정](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)을 확인한 구성이다. 워크플로 파일만 추가해도 외부 Actions가 실행되거나 저장소의 Pages 설정이 바뀐 것은 아니다.

## 일반 변경

1. 이슈에 변경할 수업 동작·기대 결과·관련 운영 결정을 기록한다.
2. 변경 브랜치에서 필요한 파일만 수정한다. 콘텐츠 수정은 JSON·공용 모듈·서버 생성본의 정합성을 확인한다.
3. 로컬 검사 후 PR을 만들고 `Checks` 결과를 확인한다. 실제 서버 변경 여부와 그 검증을 구분한다.
4. `main` 반영 뒤 Pages의 `checks → build → deploy`를 확인한다. 배포물은 `dist/`뿐이다.
5. 공개 화면과 가상 입력의 실제 연결을 확인하고 이슈·배포 기록에 결과를 남긴다.

기본 작업은 요청이 있을 때 진행한다. 이슈 양식이나 CI 파일이 자동 상주 관리·독립적 변경 권한·정기 감시를 만드는 것은 아니다.

## 오류 확인과 복구

| 증상 | 먼저 볼 곳 | 조치 |
|---|---|---|
| PR 검사 실패 | `Checks`의 실패 명령 | 실패 원인을 고친다. 검사를 건너뛰어 배포하지 않는다. |
| Pages 설정 오류 | 저장소 Pages 게시 소스·배포 환경 | 관리자가 GitHub Actions 게시와 브랜치 설정 확인 |
| 배포 성공인데 제출·공유가 안 됨 | `config.js`, 서버 배포 URL, 실제 왕복 결과 | 연결 미완료로 기록하고 설정·서버·망을 확인 |
| 전송 대기 남음 | 기기 큐와 네트워크·서버 응답 | 같은 제출 ID로 재전송. 검증 전 기기 데이터를 지우지 않음 |
| AI 오류·시간초과 | 서버 기록·대본 전환 | 같은 흐름의 대본 모드로 진행. 실제 AI 설정·정책은 관리자 확인 |
| 교사 조회 불가 | 서버 인증·교사 암호 설정 | 암호를 공개 코드에 넣지 않고 서버 설정 확인 |
| 변경 뒤 수업에 지장 | 마지막으로 확인된 커밋·서버 버전 | 해당 변경을 되돌리는 PR과 필요한 서버 버전 복구. 학생 데이터를 삭제하는 방식으로 복구하지 않음 |

Pages만 되돌려도 Apps Script 서버 버전·시트 구조가 함께 되돌아가는 것은 아니다. 클라이언트·서버·데이터 구조의 호환성을 각각 확인한다. 원인 기록에는 가상 재현과 개인정보를 제거한 오류 정보만 남긴다.

## 요청 창구

**Issues → New issue**의 오류 신고·개선 요청을 사용한다. 실제 학생 답변·이름·학번·녹음·교과서 원본·암호·AI 키를 올리지 않는다. 화면 첨부가 필요하면 가상 자료로 재현한다. 요청만 등록된 상태와 코드 반영·배포·수업 확인이 끝난 상태를 구분한다.

이번 확장은 2차시를 보존하고 4차시 모둠 대본을 추가한다. 3차시 자동 입론 제출·불러오기와 녹음 업로드는 별도 범위다. 실제 AI는 보류이며 4차시를 AI 연결 완료로 표시하지 않는다. 스펙 전체를 완료 목록으로 확대하지 않는다.

## 2·4차시 확장 관리

- 첫 화면 상위 2·4차시와 기존 2차시 내부 학습/활동·공유를 구분한다. 예전 2차시 주소·세션·개인 초안은 유지한다.
- 교사 개방 설정은 `set_lessons`의 PASSCODE 인증으로 2·4만 저장한다. 공개 config의 15초 확인은 화면 반영 수단이고 서버도 학생 요청마다 닫힘을 검사한다. 닫힘·재개가 초안을 지우거나 완료를 초기 진행으로 되돌리지 않게 한다.
- 모둠 기록은 대표 포함 같은 반 4~5명 전체 학번과 모둠명으로 검증한다. 대표가 바뀌어도 반＋정규화 모둠명의 최신 이력으로 묶고 실명은 추가하지 않는다. 명단·원문은 교사 인증 조회에만 허용한다.
- 콘텐츠 변경은 2차시 `data/content.json`↔`src/core/content.js`, 4차시 `data/lesson4.json`↔`src/core/lesson4-content.js`를 각각 맞춘다. `node backend/sync.mjs`로 두 엔진·콘텐츠의 GAS 생성본과 스키마를 갱신한다.
- 서버 5.1.0은 소유자가 코드 전체 교체→`setupDB()`→기존 배포 새 버전 적용을 해야 한다. 이미 확인한 2차시 실서버와 새 4차시 확장 적용 상태를 구분한다. 기존 탭·열·행·암호·시트 ID를 보존한다.
- 실제 AI 호출은 이번에 진행하지 않는다. L2의 기존 선택적 어댑터 설명이나 저장소 함수의 존재를 L4 AI 연결·연령/학교 승인 완료로 해석하지 않는다.

| 증상 | 확인과 조치 |
|---|---|
| 4차시가 준비 상태·교사 개방 제어 미지원 | 현재 서버의 5.1.0 적용 여부와 implementedLessons 확인. 최신 UI만으로 해결 완료라 하지 않음 |
| 닫은 차시에서 전송 대기 | LESSON_CLOSED를 자동 반복 전송하지 않고 재개 후 명시적 재전송. 초안·원래 제출 ID 보존 |
| 모둠 복원·대표 변경 충돌 | 학번 명단·반·정규화 모둠명·세션키 대조. 기록 삭제나 새 개인 결과 생성으로 우회하지 않음 |
| 대본 피드백의 한계 | 출처·연결·응답 태도 표현에 대한 규칙 피드백임을 확인. 의료 진단·실통계 진위·점수 판정으로 확대하지 않음 |

정확한 요청·열 확장·반환 형태는 [4차시 구현 계약](LESSON4_IMPLEMENTATION_CONTRACT.md), 실제 적용 시점은 [서버 갱신 안내](SERVER_UPDATE.md)와 [배포 상태](DEPLOYMENT_STATUS.md)를 따른다.
