# 처음 한 번 하는 계정 소유자 설정

데이터베이스는 이미 개인 계정 소유의 비공개 Google Sheets로 만들어져 있다. 새 시트를 만들거나 학생에게 시트 공유 권한을 줄 필요는 없다. 아래 작업은 PC 브라우저에서 진행한다.

## 1. 시트에서 Apps Script 열기

1. 전달받은 데이터베이스 시트를 연다. 오른쪽 위 계정이 요청한 개인 계정인지 확인한다.
2. 상단 **확장 프로그램 → Apps Script**를 누른다. 새 탭이 열리면 프로젝트 이름을 **채움 토론발표 서버**로 정한다.
3. 기본 `Code.gs` 안의 `myFunction` 코드를 모두 지운다.
4. 이 저장소의 [`backend/ServerBundle.gs`](../backend/ServerBundle.gs)를 연다. **Raw**로 전체 내용을 확인하고 전체 선택·복사하여 `Code.gs`에 붙여 넣는다. 파일 이름이 Code.gs여도 된다. `Native.gs`나 `service.js`를 추가로 넣지 않는다.
5. 저장한다. 이 파일에는 비밀값이 없으며 키·암호를 코드에 적지 않는다.

## 2. 스크립트 속성 설정

1. 편집기 왼쪽 **프로젝트 설정(톱니바퀴)**을 누른다.
2. **스크립트 속성 → 스크립트 속성 추가**에서 다음 항목을 추가하고 저장한다.

| 속성 | 입력할 값 |
|---|---|
| `PASSCODE` | 선생님만 아는 교사 화면용 긴 암호. 예제 암호를 그대로 사용하지 않음 |
| `AI_PROVIDER` | 우선 `none` |

시트에서 연 프로젝트는 `setupDB()`가 `SPREADSHEET_ID`를 자동 등록한다. 별도 프로젝트에서 연 경우에만 해당 속성에 실제 시트 ID를 입력한다. 암호·API 키는 채팅이나 GitHub 이슈에 보내지 않는다. AI 공급자·모델·API 키는 첫 데이터 연결을 확인한 뒤 선택적으로 설정할 수 있다.

## 3. 초기 실행과 권한 승인

1. 왼쪽 **편집기**로 돌아간다.
2. 위쪽 함수 선택에서 **setupDB**를 고르고 **실행**을 누른다. `doGet`이나 `doPost`를 직접 실행하지 않는다.
3. Google 권한 안내가 뜨면 사용하는 개인 계정을 확인하고, 직접 붙여 넣은 이 프로젝트가 시트를 읽고 쓰도록 승인한다. 승인 화면이나 차단 메시지가 이해되지 않으면 오류 문구만 알려 준다.
4. 실행 완료를 확인한다. 기존 탭이나 행을 삭제하지 않고 빠진 항목만 추가한다.

## 4. 웹앱으로 배포

1. 오른쪽 위 **배포 → 새 배포**를 누른다.
2. 유형 선택의 톱니바퀴에서 **웹 앱**을 고른다.
3. 설명은 `2차시 서버 최초 연결`처럼 적는다.
4. **실행 사용자: 나**를 선택한다.
5. **액세스 권한: 모든 사용자**를 선택한다. 학생이 Google 로그인 없이 앱을 쓰도록 하는 서버 접근 설정이다. 원문 시트의 비공개 공유 설정은 유지한다. `Google 계정이 있는 모든 사용자`와 구분한다.
6. **배포**를 누르고 필요한 권한 안내를 확인한다.
7. **웹 앱 URL**을 복사한다. 주소 끝은 `/exec`여야 한다. `/dev`나 편집기 주소가 아니다.
8. 이 `/exec` URL만 작업 대화에 보낸다. 이것은 프런트가 사용할 공개 API 주소이며 교사 암호를 붙여 보내지 않는다.

서버는 공개 API에서 익명 집계만 반환하고 교사 조회에는 PASSCODE를 검사한다. 시트 자체를 링크 공개로 전환하지 않는다. API 주소를 받은 뒤 제출·집계·교사 화면의 실제 연결을 별도로 검증한다.

## 5. GitHub Pages 최초 설정

1. [`toronbalpyo`의 Pages 설정](https://github.com/blink-24/toronbalpyo/settings/pages)을 연다.
2. **Build and deployment → Source**에서 **GitHub Actions**를 선택한다.
3. 저장소 **Actions**의 **GitHub Pages** 실행 결과를 확인한다. 이미 실패한 실행이 있으면 해당 실행의 **Re-run all jobs**를 누를 수 있다.
4. 배포가 성공하면 Actions 또는 Settings → Pages에 표시된 실제 사이트 주소를 사용한다.

코드가 main에 반영되어도 Pages 설정과 서버 URL 연결이 끝나기 전에는 수업용 연결이 완료된 상태가 아니다. `/exec` URL을 받은 뒤 담당 에이전트가 공개 설정 수정, 검사, PR·병합, 실제 왕복 확인을 이어서 진행한다.

## 이후 서버 코드를 바꿀 때

Apps Script 편집기의 코드를 바꾼 뒤 **배포 → 배포 관리 → 기존 배포 수정(연필) → 새 버전 → 배포**로 갱신한다. 기존 배포를 갱신하면 같은 `/exec` URL을 유지할 수 있다. 새 배포를 별도로 만들었으면 새 URL을 프런트에 다시 연결해야 한다.

현재 연결 기능에는 Apps Script 프로젝트 편집·권한 승인·배포와 GitHub Pages 최초 설정 기능이 없다. 이 최초 단계는 소유자의 화면 작업이 필요하다.

공식 안내: [Google 웹앱 배포](https://developers.google.com/apps-script/guides/web), [GitHub Pages 게시 소스](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site).
