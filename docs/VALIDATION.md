# 검증 기록

2026년 10월 26일, 수업안 v6·웹앱 스펙 v5 기준 로컬 코드 검사 결과다.

- `npm test`: 34개 통과. 대본의 32조합, 기준·겨냥 대상·심각도, 피드백 원문 예시, 첫 답 잠금, 2답 종료, 개인정보·허용값·길이·수식 입력, 중복 제출, 서버 재계산, 교사 인증, 익명 집계, AI 실패·늦은 응답 복구, 초안·전송 큐·전체 대담 프로토콜을 포함한다.
- `npm run check`: 모듈 문법·상대 import·공개 키 형태·UTF-8·모바일 viewport 검사 통과. 공개 JS 전체를 합쳐 gzip 35,339바이트로 200KB 기준 이내다.
- `node backend/sync.mjs --check`: 브라우저·Node 엔진과 Apps Script 번들·콘텐츠 일치.
- `npm run build`: 공개 허용 목록만 `dist/`로 복사. 서버 코드·프롬프트·문서·시험·사용자 원본은 배포물에 포함하지 않는다.
- DB 양식: 실제 서버의 9탭·155개 헤더와 일치. 설정 8행 외 데이터가 없고 학생·샘플·비밀값을 넣지 않았다.

시험은 Node와 Google 서비스의 모형 저장소에서 실행했다. 실제 Google Sheets 쓰기·교사 암호 조회·브라우저 CORS·GitHub Actions·Pages·학교 태블릿·AI 공급자 호출의 검증 결과가 아니다. 사용 가능한 브라우저 검사 경로가 없어 실제 화면 실행·스크린샷 검사는 하지 않았다. 모바일 배치와 접근성은 HTML·CSS·상태 및 네트워크 코드 구조를 확인한 범위다.

외부 계정 연결과 배포 후에는 가상 입력으로 실제 왕복을 확인하고 이 기록에 그 결과를 추가한다. 현재 상태는 [DEPLOYMENT_STATUS.md](DEPLOYMENT_STATUS.md)에 있다.

## 2026년 10월 27일 추가 확인

- 동일 구현의 로컬 34개 자동시험·프로젝트 검사·번들 일치·빌드를 재실행해 통과했다.
- GitHub PR #1의 Checks가 실제 성공했고, 검증된 구현을 main에 병합했다. 원격 Git tree와 로컬 39개 텍스트 소스의 tree SHA가 일치한다.
- main의 Pages 실행도 테스트·검사·빌드와 공개 파일 경계 검사를 통과했다. 저장소 Pages가 활성화되지 않아 Configure GitHub Pages에서 Not Found로 실패했으며 실제 사이트는 게시되지 않았다.
- 요청한 개인 계정 소유·비공개 Google Sheets를 실제 생성했다. 메타데이터와 셀 읽기로 9탭·155헤더·초기 설정 8행·한국 시간대를 확인했다. 학생 기록은 넣지 않았다.
- Google에서 내보낸 XLSX를 Artifact Tool로 가져와 9탭의 채워진 영역을 확인했다. 영문 헤더는 잘림·겹침이 없었다. config 한글 값은 보존됐지만 로컬 import/render에서 미표시되며 변환 전 원본 XLSX에서도 같은 현상이 재현됐다. 이 경로의 한글 시각 검증은 호환 한계가 있고 Google 실제 화면 오류로 단정하지 않는다.
- Apps Script 최초 권한 승인·배포와 실제 브라우저/시트 왕복은 아직 대기 중이다. Node 모의시험이나 시트 생성 성공을 실서비스 연결 검증으로 바꾸어 기록하지 않는다.

## 서버 연결·사이트 최초 게시

- 사용자 확인으로 초기 함수 실행·웹앱 배포를 완료했고 실제 /exec 주소를 PR #4로 연결했다.
- 실제 Google 서버 접속 검사 실행 40481995409 성공: 공개 ping, 시트 config 조회, 익명 집계 허용 필드, 암호 없는 교사 조회 거부, 잘못된 학번 POST 저장 전 거부, 총 5개 통과. 학생 기록을 생성하거나 교사 암호를 읽지 않았다.
- 사용자가 Pages를 활성화한 후 실행 40481995416의 2번째 시도에서 공개 정적 파일 준비·업로드·게시 성공. 실제 배포 환경 URL은 https://blink-24.github.io/toronbalpyo/ 이다.
- 배포 후 HTTP 파일 확인 단계를 워크플로에 추가했다. 실제 정상 제출 저장·브라우저 실행과 CORS·교사 암호 로그인·학교 기기 운영·AI 공급자 호출은 별도 검증 대상이다.

## 자체 검토 완료 범위

- PR #6에서 입력·초안 보존, API 주소 고정, BUSY·수동 재전송 복구, 제출 후 상태 보호·부분 저장 복구·캐시 장애 보완을 추가했다.
- Node 53개 전부 통과, JS 공개 모듈 gzip 35,435바이트, 프로젝트 검사·생성 GAS 일치·정적 빌드 통과.
- Chromium 첫 게시 사이트 데스크톱 검사에서 3답·실제 저장·중복 ACK를 확인했다. 첫 시도의 공유 버튼 중복 선택자는 검사 코드를 수정했고, 모바일 학번 초기화는 앱 결함을 수정했다.
- Chromium 수정 후보 검사 40486318647에서 데스크톱 1440×1000과 모바일 390×844 두 흐름이 통과했다. 후보 정적 파일을 CI의 로컬 HTTP에서 열고 실제 배포 Google API를 사용했다. 데스크톱은 3답·대본, 모바일은 오프라인 2답 조기 종료·재연결 저장이다. 원격 질문·최종 ACK·같은 제출 ID의 duplicate=true·익명 공유를 실제 브라우저 fetch로 확인했다.
- Google Sheet에서 생성한 세션 3개 각각 정확히 한 제출 행, 문항 수 3·3·2, mode script·script·script-local, 조기 종료값을 확인했다. 생성 세션 ID가 일치하는 제출 3·대담 18·진행 28행만 정리했고 재조회에서 참조가 없음을 확인했다. 기존 사용자 진행·설정은 건드리지 않았다.
- 첫 브라우저 이미지 12개와 통과 시 이미지 17개를 개별 시각 검토했다. 새로 판정된 잘림·가로 넘침·읽기 불가 문제는 없었다. 모바일 sticky 버튼이 전체 페이지 캡처에 겹쳐 보이는 현상은 실제 결함으로 단정하지 않았으며 각 입력·인용·제출 동작은 자동 브라우저에서 통과했다.
- 수정분 Pages 실행 40486746828 게시 및 공개 HTTP 파일 검사 성공. 실제 교사 암호 로그인·학교 기기/망·선택적 AI 호출은 이번 검사에 포함하지 않았다.
- 서버 추가 보완은 생성 코드의 로컬/CI 검증만 완료했다. 현재 Apps Script 서버에는 최초 코드가 실행 중이므로 소유자의 기존 배포 새 버전 적용이 남는다.


## 2·4차시 확장 검증(5.1.0 후보)

- 첫 후보 Node 97개 모두 통과. 기존 2차시 회귀를 유지하고 4차시 양 입장·3/4/5문항·입론 단서·자료 인용·대표 변경·모둠 집계·차시 닫힘 경합·최대 이스케이프 입력·중복·부분 저장 복구를 검사했다.
- Node와 생성 GAS 4차시 엔진이 같은 질문·피드백을 내는지 6조합에서 대조했고, 실제 Apps Script 저장 어댑터의 28→39열 확장·기존 행/헤더/설정 메모 보존·빈 개방값 기록을 VM에서 검사했다.
- 첫 [두 차시 브라우저 검사](https://github.com/blink-24/toronbalpyo/actions/runs/40494071671) 통과: 데스크톱 4답, 모바일 크기 3답 조기 종료·전송 실패 후 재전송, 내려받기, 모둠별 교사 조회, 무암호 설정 변경 거부, 두 차시 모두 닫기. 실제 서비스 모듈에 메모리 저장소를 연결한 합성 시험이며 실제 Google 저장/교사 암호/AI 호출은 없다.
- 첫 후보 이미지에서 학생이 반대 입장일 때 상대자 이름이 고정된 문제를 발견해 양 입장의 상대자 표시를 보완했다. 후속 검사에서 진행 중 닫힘·재개 초안 보존과 최초 서버 호환을 추가한다.
- 생성 서버 일치·프로젝트 문법/import/비밀키 형태·정적 빌드를 검사했다. 원본 자료는 수정하지 않았고 Pages에는 정적 허용 파일만 올린다.
- 실제 Google 서버의 5.1.0 적용과 추가 11개 헤더 확인, 실제 교사 암호 인증·4차시 저장은 소유자 코드 교체/초기 실행/기존 배포 갱신 후 수행한다.

실행 코드 재검토 후 Node 전체 **107/107** 통과, 공개 JS gzip **58,159바이트**. 학생 찬성/반대에 따라 상대 토론자 표시가 바뀌는 회귀와 오프라인 backoff 뒤 동일 제출 ID 저장을 추가했다.

최종 추가 회귀: 기존2차시의 상대 표시와 온라인 재접속 시 닫힘·backoff 보존을 포함해 **109/109** 통과, 공개 JS gzip **58,175바이트**. 후속 브라우저 후보에서 기존2차시3답 제출도 함께 확인한다.


최종 브라우저 실행 [40494815236](https://github.com/blink-24/toronbalpyo/actions/runs/40494815236)에서 기존2차시3답 저장과 4차시 양 입장, 모바일 오프라인 재전송, 교사 명단·익명 투사, 진행 중 닫힘→초안 보존→열기, 최초 서버 호환을 모두 통과했다. PR #9 병합 뒤 [Pages 40495061769](https://github.com/blink-24/toronbalpyo/actions/runs/40495061769) 게시·공개 파일 HTTP 확인도 통과했다. 첫 후보 PNG11개를 개별 시각 검토했다.

게시 후 실제 API 조회에서 classCount=13을 확인했다. 과거의 11반 상수와 달라 접속 검사 40495061815가 실패했고, 이를 근거로 조회 검사를 유효한 운영 범위 검사로 바꾸고 교사용 두 목록이 config.classCount를 따르게 수정했다. 운영 설정을 덮어쓰지 않았으며 13반 목록 회귀를 포함한 Node109개 통과, gzip58,183바이트다. 브라우저 fixture도13반으로 검사한다.

추가 브라우저 검사 환경에서 Chromium 의존성 설치가 지연되어 GitHub runner의 설치된 Chrome이 있으면 Playwright가 이를 사용하도록 했다. 설치가 필요할 때에는3분 마감을 둔다. 애플리케이션 코드·시험 시나리오는 유지한다.


새 배포 연결: 실제 API 실행40497640714에서5.1.0/구현2·4/운영13반/현재2만열림/4차시4문항/대본모드 확인 및 무암호교사조회·설정변경 거부를 통과했다. 실제학생행·개방설정을 변경하지 않은 검사다. 기존 DB l4_sessions A1:AB1의28헤더를 검사한 뒤 AC1:AM1에11헤더를 추가하고 A1:AM1의39헤더 완전일치를 다시 확인했다. 확장전후 frozenRowCount1·기존서식·기존열을 유지했다. Google 화면 렌더 대신 API 서식값으로 확인했으며 실제 모둠 정상제출은 미검증이다.

새 주소의 실제 브라우저 연결 확인용 qa/connection-browser.mjs를 추가했다. 저장/교사 암호 입력 없이 공개config와2·4차시 화면만 읽고, 모든POST를 차단하여 뜻하지 않은 기록 생성을 방지한다. 이 검사는 모의저장소의 전체활동검사와 구분한다.
