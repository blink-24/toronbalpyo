# 자체 검토 후 서버 보완 적용

프런트는 GitHub Pages 배포로 갱신된다. Apps Script는 별도 서비스이므로 GitHub의 서버 파일을 수정하거나 Pages를 갱신해도 현재 실행 중인 서버 코드가 자동으로 바뀌지는 않는다.

## 현재 차이

사용자가 최초 배포한 서버는 기본 활동·정상 제출·중복 제출 경로를 실제로 확인했다. 자체 감사에서 추가한 아래 보완은 저장소의 최신 `backend/ServerBundle.gs`에 포함되어 있으며, 현재 Apps Script에는 소유자의 코드 교체·기존 배포 새 버전 적용이 필요하다.

- 제출 후 늦게 도착한 질문·피드백이 완료 상태를 이전 단계로 돌리지 않도록 보호
- 제출 행 저장 뒤 진행 상태 쓰기가 실패한 경우 같은 제출 재시도로 완료 상태 복구
- 로그·제출 중복 방지 캐시 쓰기가 실패해도 실제 시트 저장과 중복 방지 유지
- AI 호출 한도 기록 실패 시 AI를 호출하지 않고 대본으로 진행
- 수식 방지 처리 후 실제 셀 문자열의 길이 제한 검사

## 소유자 작업

1. 기존 데이터베이스 시트의 **확장 프로그램 → Apps Script**를 연다.
2. [최신 서버 코드 전체](https://github.com/blink-24/toronbalpyo/raw/refs/heads/main/backend/ServerBundle.gs)를 전체 복사한다.
3. `Code.gs`의 현재 코드 전체를 새 코드로 교체하고 저장한다. 코드 4부분 뒤에 추가하는 방식이 아니라 **전체 교체**다. 기존 스크립트 속성의 교사 암호·시트 ID는 유지한다.
4. **배포 → 배포 관리 → 기존 웹앱의 연필 아이콘 → 버전: 새 버전 → 배포**로 갱신한다. 기존 배포를 갱신하면 같은 `/exec` 주소를 유지할 수 있다.
5. 갱신 완료 후 실제 서버에 대한 검사를 다시 진행한다. 암호나 API 키를 대화·저장소에 보내지 않는다.

이 보완은 스프레드시트의 탭·머리글을 바꾸거나 기존 기록을 삭제하지 않는다. 소유자 배포가 끝나기 전에는 새 서버 보완을 실서비스 적용 완료로 표현하지 않는다.
