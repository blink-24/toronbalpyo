# 키워드 대본 서버 갱신(5.2.0)

30개 예상 쟁점과 찬반별2관점120개 대응 대본을 적용한다. 현재 실제 서버5.1.0은 갱신 전까지 기존 대본으로 작동한다. Pages 게시만으로 Apps Script 코드가 바뀌지 않는다. 대화에서는 아래 작업을 한 단계씩 안내한다.

## 소유자 작업 순서

1. [서버 코드 전체](https://github.com/blink-24/toronbalpyo/blob/main/backend/ServerBundle.gs)를 연다. 코드 영역의 복사 버튼으로 전체를 복사하고 기존 Apps Script의 `Code.gs` 내용을 전체 교체한 뒤 저장한다. 기존 코드 뒤에 덧붙이지 않는다. 기존 스크립트 속성·암호·시트ID는 유지한다.
2. **배포 → 배포 관리 → 현재 웹앱의 연필 아이콘 → 버전: 새 버전 → 배포**를 선택한다. 기존 배포를 갱신해 같은 `/exec` 주소를 유지한다. 새 배포를 만들었다면 새주소를 공유해야 화면 설정도 맞출 수 있다.
3. 실제 공개 `ping.version=5.2.0`, `config.l4ScriptVersion=1.1.0`을 확인한다. 실제 AI는 계속 보류이며 `l4AiEnabled=false`다. 서버 갱신 전 기존 대본의 동작 검사를 새 대본 적용 완료로 보지 않는다.
4. 학생 화면을 강력 새로고침하고 새 모둠 활동에서 새 대본을 확인한다. 이미 진행 중인 모둠은 대본1.0.0을 유지한다. 교사의4차시열기와 실제 정상 모둠 제출은 별도로 확인한다.

이번 변경은 기존39열 스키마를 유지하므로 `setupDB()` 재실행이 필수는 아니다. 기존 코드의 초기설정 함수는 계속 기존 행·설정·머리글을 보존한다. 사용자13반과 차시 개방 설정은 변경하지 않는다. 암호나API키를 대화에 보내지 않는다.

## 복구와 버전

화면5.2.0은 서버가 새대본을 알리기 전 기존1.0.0을 사용한다. 새서버는1.0.0/1.1.0을 모두 지원하며 저장 중 세션을 재계획하지 않는다. 갱신 이후1.1.0 세션이 생긴 상태에서 서버만5.1.0으로 되돌리면 해당 새세션을 이어갈 수 없으므로5.2.0을 유지한 채 복구한다. 기존2차시와 원본 자료는 그대로다.
