# 4차시 AI 토론 키 설정 안내(서버 5.4.0)

계정 소유자가 Apps Script에 Upstage Solar 키를 넣고 연결을 확인하는 순서다. PC 브라우저에서 진행한다. 키·암호는 채팅·GitHub 이슈·시트 셀에 붙여 넣지 않는다. 키가 노출되었다고 생각되면 Upstage 콘솔에서 해당 키를 삭제하고 새로 발급한다.

## 먼저 알아 둘 점

- 이번 버전은 **Solar만 사용**한다. Gemini 검색은 구현하지 않았다. 이유는 [AI 토론 스펙](LESSON4_AI_DEBATE_SPEC.md) 8절(만 18세 조항, 검색 결과 이용 제한)이다.
- 받아 둔 **Google AI Studio(Gemini) 키는 넣지 않는다.** 특히 `AI_PROVIDER`를 `gemini`로 바꾸거나 `AI_API_KEY`에 넣으면 2차시 기존 AI 대담 코드가 켜진다. `AI_PROVIDER`는 `none` 그대로 둔다.
- 키를 넣어도 교사 화면에서 4차시 활동 방식을 **AI 토론**으로 바꾸기 전에는 학생에게 대본 활동만 보인다.
- 실제 학생에게 열기 전에 스펙 17절의 확인 항목(Upstage 이용약관의 연령·데이터 조항, 학교 승인, 학생 고지)을 먼저 확인한다.

## 1. 서버 코드 교체

1. 데이터베이스 시트에서 **확장 프로그램 → Apps Script**를 연다.
2. 저장소의 [`backend/ServerBundle.gs`](../backend/ServerBundle.gs)를 열어 **Raw** 화면에서 전체를 복사한다.
3. 기존 `Code.gs` 내용을 모두 지우고 붙여 넣은 뒤 저장한다(디스크 아이콘 또는 Ctrl+S).

## 2. 스크립트 속성에 키 넣기

1. 편집기 왼쪽의 **톱니바퀴(프로젝트 설정)**를 누른다.
2. 아래쪽 **스크립트 속성**에서 **스크립트 속성 수정**을 누른다.
3. **스크립트 속성 추가**를 눌러 아래 세 항목을 넣는다. 속성 이름은 대소문자까지 똑같이 쓴다.

| 속성 | 값 | 설명 |
|---|---|---|
| `L4_DEBATE_PROVIDER` | `solar` | 이미 `none`이 있으면 값을 `solar`로 바꾼다 |
| `SOLAR_API_KEY` | Upstage 콘솔에서 받은 키 | 앞뒤 공백 없이 붙여 넣는다 |
| `SOLAR_MODEL` | `solar-pro4` | Upstage 문서 발췌 기준 현재 모델 이름. 콘솔의 모델 목록에서 이름을 한 번 확인한다 |

4. **스크립트 속성 저장**을 누른다.
5. 기존 `PASSCODE`, `SPREADSHEET_ID`, `AI_PROVIDER`(`none`)는 지우거나 바꾸지 않는다.

선택 속성(없으면 기본값을 쓴다):

| 속성 | 기본값 | 바꿀 때 |
|---|---|---|
| `L4_DEBATE_DAILY_CALL_MAX` | `400` | 하루 전체 Solar 호출 상한. 한 모둠은 문답 2회 기준 약 12회 호출 |
| `L4_DEBATE_SESSION_CALL_MAX` | `20` | 한 모둠 토론의 호출 상한(재시도 포함) |
| `SOLAR_MAX_TOKENS` | `2000` | 응답이 중간에 끊기면 늘린다 |
| `SOLAR_REASONING_EFFORT` | 비움 | 응답이 너무 느리거나 Upstage 문서가 값을 안내할 때만 넣는다 |
| `SOLAR_JSON_MODE` | `json_object` | `testSolarConnection`이 `AI_REQUEST_FAILED`(HTTP 400)를 낼 때 `off`로 바꿔 다시 확인한다 |
| `SOLAR_BASE_URL` | `https://api.upstage.ai/v1` | Upstage가 주소를 바꾸었을 때만 |

## 3. 초기 실행과 연결 확인

1. 편집기 위쪽 함수 선택에서 **setupDB**를 고르고 **실행**한다. 권한 안내가 나오면 내 계정을 확인하고 허용한다. `l4_debate_turns`·`l4_debates` 탭과 `config`의 `l4Mode` 등 세 줄이 추가된다. 기존 탭·행은 지우지 않는다.
2. 함수 선택에서 **testSolarConnection**을 고르고 **실행**한다. 아래 **실행 로그**를 본다.

| 로그 | 뜻과 조치 |
|---|---|
| `Solar 연결 성공 · 모델 … · …ms` | 정상 |
| `설정이 더 필요합니다: …` | 표시된 속성 이름을 2절대로 넣는다 |
| `AI_AUTH` (HTTP 401·403) | 키를 다시 복사해 넣는다. 콘솔에서 키가 살아 있는지 확인한다 |
| `AI_REQUEST_FAILED` (HTTP 400·404) | 모델 이름을 확인한다. 그래도 같으면 `SOLAR_JSON_MODE`를 `off`로 바꿔 본다 |
| `AI_RATE_LIMITED` (HTTP 429) | Upstage 사용량·결제 상태를 확인한다 |
| `AI_UPSTREAM`·`AI_NETWORK` | 잠시 뒤 다시 실행한다 |

3. 함수 선택에서 **testDebateSample**을 고르고 **실행**한다. 수업용 가상 입론으로 만든 AI 입론 하나가 로그에 나온다. 시트에는 학생 기록을 쓰지 않는다. `결과: ai`면 정상이고, `unavailable · AI_OUTPUT_REJECTED:…`면 검증 규칙에 걸린 이유가 함께 나온다. 같은 이유가 반복되면 결과를 알려 주면 조정한다.

## 4. 웹앱 새 버전 배포

1. 오른쪽 위 **배포 → 배포 관리**를 연다.
2. 기존 배포의 **연필(수정)**을 누르고 버전에서 **새 버전**을 고른다. 설명에 `5.4.0 AI 토론`처럼 적는다.
3. **배포**를 누른다. 기존 배포를 수정하면 `/exec` 주소가 그대로라 화면 설정을 바꿀 필요가 없다. 새 배포를 따로 만들었다면 새 주소를 알려 준다.

## 5. 교사 화면에서 켜기와 리허설

1. 웹앱의 **교사용**에서 암호로 들어간다.
2. **4차시 활동 방식**에서 **AI 토론**을 누른다. 신문 문답 수(1~3회)와 반박 단계 포함 여부를 정한다. 처음에는 문답 1회로 시간을 재 보는 것을 권한다.
3. 상태 문구가 “AI 토론으로 진행합니다”인지 본다. “Solar 설정 필요”가 보이면 2·4절을 다시 확인한다.
4. 4차시를 열고, 학생 화면에서 **가상 모둠**(실제 학생 학번이 아닌 시험용 학번·모둠명, 가상 입론)으로 찬성·반대를 한 번씩 끝까지 진행해 본다. 개인정보·대필 요청·건강 질문을 일부러 넣어 보고 거절되는지 본다.
5. 리허설 결과로 문답 수·반박 단계·호출 상한을 정하고, 교사용 화면의 **AI 토론 기록**에서 발언과 남긴 허점을 확인한다.
6. 수업에서 쓰지 않을 때는 **대본**으로 되돌린다. 진행 중이던 토론 기록은 지워지지 않는다.

## 6. 문제가 생기면

| 증상 | 확인 |
|---|---|
| 학생 화면에 AI 토론이 안 보임 | 교사 화면 모드가 AI 토론인지, 상태 문구에 “Solar 설정 필요”가 없는지, 새 버전 배포를 했는지 |
| “AI 발언을 만들지 못했어요” | 시트 `log` 탭의 `l4_debate` 줄에서 오류 코드 확인. 학생은 다시 시도하거나 대본 활동으로 바꿀 수 있다 |
| “AI 사용 한도에 도달했어요” | `L4_DEBATE_DAILY_CALL_MAX`·`L4_DEBATE_SESSION_CALL_MAX` 확인 |
| 응답이 자주 30초를 넘김 | 문답 수를 줄이거나, Upstage 문서를 확인해 `SOLAR_REASONING_EFFORT`를 조정 |

키를 바꿀 때는 2절의 속성 값만 고치면 되고 다시 배포할 필요는 없다. 코드(`Code.gs`)를 바꾼 경우에만 4절의 새 버전 배포를 다시 한다.
