# 채움 2차시 서버

이 서버는 수업안 v6와 웹앱 스펙 v5의 **2차시 개인 반대 신문 체험**을 구현한다. 3·4차시 데이터 탭은 이후 연결을 위해 준비하지만 해당 활동·녹음 업로드는 현재 열지 않는다.

## 파일과 실행

- `../src/core/engine.js`: 브라우저·Node 공용 순수 함수. 콘텐츠를 `createEngine(content)`로 주입한다.
- `service.js`: 검증·세션·저장·집계·선택적 AI를 담당하는 서버 서비스. Google 서비스는 어댑터로 주입한다.
- `Native.gs`: Apps Script의 실제 Google Sheets·LockService·PropertiesService·UrlFetchApp 어댑터다.
- `ServerBundle.gs`: 위 엔진·서비스와 `data/content.json`을 합친 자동 생성 파일이다. Apps Script 편집기에 **이 파일 한 개만** 붙여 넣는다. Native.gs 등을 중복으로 붙이지 않는다.
- `schema.json`: 9개 탭의 실제 머리글 및 초기 설정. 로컬 DB 양식도 이 파일과 비교한다.

프로젝트 루트에서 다음을 실행한다.

```bash
node backend/sync.mjs
node backend/sync.mjs --check
node --test tests/engine.test.mjs tests/backend.test.mjs
```

엔진·콘텐츠·서비스를 고쳤으면 번들을 다시 생성해야 한다. `--check`는 파일 내용이 정확히 같은지 검사하며 Google에 접속하지 않는다. 테스트는 가짜 저장소와 Google 어댑터 모형을 사용한다. 실제 배포·시트 권한·태블릿 시험을 대신하지 않는다.

## Google 계정과 초기 설정

Google 연결·외부 배포는 총괄이 담당한다. 지정한 Google 계정인지 먼저 확인한 뒤, 교사만 접근할 수 있는 시트에서 확장 프로그램의 Apps Script 편집기를 연다. 이 문서는 로컬 구현 설명이며 서버가 배포되었다는 뜻이 아니다.

1. 편집기에 `ServerBundle.gs`만 넣는다. 기존 데이터가 있다면 사본과 버전을 보존한다.
2. 프로젝트 설정의 스크립트 속성에 `SPREADSHEET_ID`와 `PASSCODE`를 설정한다. 시트에 연결된 프로젝트라면 `setupDB()`가 활성 시트 ID를 사용할 수 있다. 암호가 없으면 교사 조회는 열리지 않는다.
3. AI를 쓰지 않으면 `AI_PROVIDER=none`으로 둔다. AI 키·모델이 비어 있어도 대본 모드로 동작한다.
4. `setupDB()`를 실행한다. 기존 시트·행을 지우지 않고 빠진 탭·머리글·기본 설정만 추가한다.
5. 총괄이 계정·학교 정책·시트 공유 상태를 확인한 뒤 웹 앱 배포를 진행한다. 실행 주체와 접근 범위는 `appsscript.json`에 명시되어 있다. 배포 URL은 프런트 외부 설정에만 넣는다.

스크립트 속성 전용 항목은 `PASSCODE`, `SPREADSHEET_ID`, `AI_PROVIDER`, `AI_MODEL`, `AI_API_KEY`, `AI_RATE_PER_HOUR`다. 키·암호를 소스·시트 config·프런트·공개 저장소에 적지 않는다. 실제 모델 이름은 공급자의 사용 가능한 모델을 확인한 뒤 설정한다. 코드에 기본 모델을 임의로 지정하지 않았다.

## 대본 규칙과 기록

찬반 2 × 이유 4 × 근거 4의 32조합을 처리한다. 신뢰성·타당성·공정성 각 1개를 선택하고 심각도 내림차순, 동률이면 신뢰성→타당성→공정성 순으로 묻는다. 설정이 2개이면 앞의 두 개를 쓴다.

대상 범주는 이유·카드 내용·카드 출처·입장으로 나눈다. 특히 RN2+NB/NC/ND에서는 공정성 질문이 운전자 책임이라는 **이유**, 타당성 질문이 사고 원인에서 벌금 반대 결론으로 가는 **입장 연결**을 확인하여 중복을 피한다. 원문 질문을 임의 교체하지 않았다.

질문마다 시드에 따라 도움 자료 2장을 고른다. 시드는 기본 세션 ID이고 같은 입력에서는 같은 카드가 나온다. 존재하지 않는 도움 자료 번호와 현재 제시되지 않은 클릭 카드 ID는 거부한다. 학생이 다음 질문으로 넘긴 첫 답은 잠기며, 다른 내용으로 재전송하면 거부한다.

두 번째 답 뒤 조기 종료와 `config.l2Questions=2`를 지원한다. 실제로 답한 두 문항만 평가·저장하고 세 번째 빈 문항을 만들지 않는다. 마지막 제출에는 10~150자의 성찰을 요구한다.

## 저장소와 보호

탭은 `config`, `l2_sessions`, `ai_log`, `l3_args`, `l4_sessions`, `recordings`, `uploads`, `log`, `progress`의 9개다. config·log는 전용 머리글이며 다른 탭은 COMMON 열 다음에 자료별 열을 둔다. 같은 이름의 COMMON 열을 중복으로 만들지 않는다.

- 머리글과 기록은 뒤에만 추가한다. 기존 탭·열·데이터를 삭제하거나 기존 답변 행을 덮어쓰지 않는다.
- `submissionId`는 재시도 때 유지한다. 잠금 안에서 시트·속성 모두를 검사하므로 속성 기록이 실패한 뒤에도 이미 쓴 시트 행으로 중복을 확인한다. 같은 ID의 다른 내용은 충돌 오류다.
- 잠금은 데이터 읽기·쓰기의 짧은 구간에만 쓴다. AI 외부 호출 중에는 유지하지 않는다.
- 학번은 학년·반·번호를 검사한다. 현재 설정은 2학년·11개 반이고 번호 00은 받지 않는다. 클라이언트의 계획·피드백을 믿지 않고 서버가 콘텐츠로 재계산한다.
- 자유 글은 길이·제어 문자·이름 안내·학번·전화·이메일 패턴을 검사한다. 이 규칙은 완전한 개인정보 탐지라고 주장하지 않는다. 학생 안내와 교사의 확인을 함께 사용한다.
- 모든 저장 텍스트는 선행 공백 뒤의 `=`, `+`, `-`, `@`도 수식으로 실행되지 않게 처리한다. 칸당 2000자를 넘기지 않는다. 내부 상태는 `~` 접두사를 붙인 1999자 조각으로 나누어 저장하고 복원한다.
- `public_summary`는 설정 `publicSharing=true`일 때 집계 허용 목록만 반환한다. 학번·입론·개별 답변·성찰·세션 ID는 반환하지 않는다. 같은 주소에 `tab` 같은 매개변수를 붙여도 원문은 조회되지 않는다.
- `l2_summary`, `list`, `status` 등 교사 조회는 서버의 PASSCODE를 확인한다. 원문 시트와 로그는 별도로 교사만 공유해야 한다. 학번만으로 입장하는 학생 기능을 강한 본인 인증이라고 부르지 않는다.

## 선택적 AI와 20초 마감

Anthropic 또는 Gemini를 설정한 경우에도 질문 계획은 규칙 엔진이 먼저 정한다. AI는 그 계획의 질문 표현만 만든다. 요청에는 입론·카드·질문·답변과 계획만 포함하고 학번·반·모둠·이름·세션 ID를 넣지 않는다. 글 안의 개인정보 패턴을 서버가 다시 확인한다.

AI 응답의 JSON, 기준, 물음표, 질문별 140자, 개방형·금칙어·개인정보를 검사한다. 피드백의 문항 수·순서·판정 값도 검사하며 실패하면 해당 응답을 대본으로 바꾼다. AI 판정과 규칙 판정은 별도 열에 함께 저장한다. 호출 한도는 기본 학생별 시간당 30회다.

Apps Script `UrlFetchApp.fetch`에는 `timeoutSeconds` 옵션을 넣지 않는다. 브라우저는 20초에 요청 대기를 끝내고 `script-local`로 이어 간다. 서버도 반환 후 경과 시간을 확인한다. 늦게 온 응답은 브라우저가 무시하고, 서버에서는 이미 답한 차례나 완료 상태를 예전 질문으로 되돌리지 않는다.

현재 실제 AI 키·Google 배포가 연결되지 않은 환경에서는 이 경로가 실서비스로 검증되었다고 말하지 않는다. 기본 `none`의 대본·재전송·서버 검증은 로컬 테스트로 확인한다.
