# 채움 토론발표 교실

화법과 언어 수업의 **2차시 개인 학습·반대 신문 체험**과 **4차시 모둠 반대 신문 대본**을 제공하는 웹앱이다. 첫 화면에서 2차시·4차시를 고르며, 기존 PPT 학습·개인 활동·결과 공유는 2차시 안에 유지한다. 기존 `#/learn`·`#/lesson2` 주소도 2차시로 연결한다.

이번 4차시는 실제 AI 연결을 보류한 사용자의 선택에 따라 **대본 모드**로 구현한다. 모둠 입론에 맞춰 준비한 질문과 가상 자료를 선택하며 외부 AI를 호출하지 않는다. 저장소의 서버 버전은 `5.1.0`이고 기존 2차시 교육 콘텐츠 `5.0.0`과 구분한다. 현재 실행 중인 Apps Script에는 소유자의 새 서버 코드 적용이 필요하다. 실제 적용·검증·배포 상태는 [배포 상태](docs/DEPLOYMENT_STATUS.md)와 [서버 갱신 안내](docs/SERVER_UPDATE.md)를 따른다.

## 수업 흐름

| 차시 | 활동과 입력 | 대담·기록 |
|---|---|---|
| 2 | 개인 18분. 학번으로 입장하고 스마트폰 보행 벌금 논제의 입장·이유·근거를 고름 | 기본 3질문, 2답 뒤 조기 피드백. 기존 학습 19장·입론 수정·저장·익명 공유 유지 |
| 4 | 3차시와 같은 4~5인 모둠. 대표 포함 모든 모둠원 학번과 모둠명, 작성한 ①·⑤ 입론 입력 | 의료 상담 도우미의 공공 도입 논제. 기본 4질문(3~5), 질문마다 가상 자료 2~3개. 3답 이상 조기 종료·피드백·성찰·모둠 기록 |

4차시의 ① 입론은 20~1500자, ⑤는 선택·최대 1500자이며 앱이 대필하지 않는다. 답변은 600자, 성찰은 10~150자다. 모둠명과 전체 학번은 교사 전용 기록이며 실명을 추가하지 않는다. 익명 공유에는 모둠명·명단·입론·답변·성찰 원문을 내보내지 않는다.

모든 체험용 도움 자료에는 **수업용 가상 자료**를 표시한다. 4차시는 실제 건강 조언이나 새 의료 통계를 만들지 않고 제시문의 출처·정책 논증 단서를 검토한다. ⑦의 불명확한 의료 잡지 설문은 검토용 오류이며 카드 5·6은 사용 보류다. 원본 수업 자료와 교과서 202쪽 입론의 긴 본문은 앱에 복제하지 않는다.

## 차시 개방과 서버 적용

교사는 서버 인증을 거쳐 2차시·4차시를 각각 열거나 닫는다. 기본 `acceptLessons='2'`를 유지하므로 4차시는 처음에는 닫혀 있다. 프런트는 공개 설정을 15초 간격으로 확인하며, 닫힌 차시의 진입·다음 동작을 막고 초안은 보존한다. 서버도 학생 요청마다 개방 여부를 검사한다.

새 UI가 있다는 사실만으로 이전 서버에 4차시가 연결된 것은 아니다. 서버가 `implementedLessons:[2,4]`를 지원하기 전에는 4차시와 교사 개방 제어를 준비 상태로 둔다. 새 서버는 코드 전체 교체→`setupDB()`→기존 배포 새 버전 적용을 한 번에 진행한다. 기존 탭·열·학생 기록은 삭제하지 않는다. 3차시 입론 자동 제출·불러오기와 녹음 업로드 앱은 별도 범위다.

## 로컬 확인

Node.js 22 이상에서 실행한다. 외부 npm 의존성 설치는 필요 없다.

```bash
npm test
npm run check
npm run build
```

`dist/`만 공개용 정적 파일이다. Python 3가 있다면 다음과 같이 확인한다.

```bash
python3 -m http.server 4173 --bind 127.0.0.1 --directory dist
```

브라우저에서 `http://127.0.0.1:4173`을 연다. 로컬 모의시험·브라우저 확인·실제 Google 왕복·배포·학교 기기 시연은 서로 구분한다.

## 연결·운영

대상 저장소는 `blink-24/toronbalpyo`다. 계정 소유자 작업은 [설정 안내](docs/OWNER_SETUP.md), 일반 수정·복구는 [유지보수 안내](docs/MAINTENANCE.md), 서버 구조는 [backend 안내](backend/README.md)를 따른다. 교사 암호·시트 ID·AI 키는 서버 설정에서 관리하고 공개 코드나 이슈에 넣지 않는다. 현재 4차시의 실제 AI 연결은 보류이며 `AI_PROVIDER=none`을 유지한다.

게시 앱은 `config.js`에 지정한 공개 `/exec` 주소만 사용한다. API 주소 입력이나 기기별 임의 주소 덮어쓰기는 제공하지 않는다. 연결이 끊기면 기기 기록을 전송 대기로 보존하며 실제 서버의 성공 응답을 받기 전까지 제출 완료로 표시하지 않는다.

PR의 `Checks`는 읽기 권한으로 시험·검사·빌드를 수행한다. `main` 검사 통과 뒤 `dist/`만 GitHub Pages에 게시한다. 서버·문서·시험·원본은 Pages 배포물에 포함하지 않는다. GitHub 서버 파일이나 Pages를 바꿔도 현재 Apps Script 코드가 자동으로 바뀌지 않는다.

오류·개선 요청은 **Issues → New issue**에 가상 재현으로 남긴다. 학생 실데이터·명단·답변·녹음·교과서 원본·암호·키를 올리지 않는다. 이슈 창구가 자동 상주 관리나 독립적 변경 권한을 만드는 것은 아니다.

개발 지침은 [AGENTS](AGENTS.md), 기존 2차시 계약은 [API_CONTRACT](docs/API_CONTRACT.md), 이번 확장은 [4차시 구현 계약](docs/LESSON4_IMPLEMENTATION_CONTRACT.md), 자료 근거는 [CONTENT_TRACE](docs/CONTENT_TRACE.md)를 참고한다.
